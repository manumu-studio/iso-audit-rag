# Ubiquitous Language -- iso-audit-rag

Shared vocabulary for all AI sessions, code, docs, and conversations. Use these terms consistently.

## RAG Pipeline

| Term | Definition |
|------|-----------|
| **Chunk** | A segment of text extracted from a source document, sized for embedding. In this project: one clause or control from NIST SP 800-53. |
| **Embedding** | A fixed-length vector of floats representing the semantic meaning of a chunk. Generated by an embedding model (e.g. text-embedding-3-small). |
| **Vector store** | A database that stores embeddings and supports similarity search. In this project: PostgreSQL + pgvector. |
| **Ingestion pipeline** | The offline process: PDF --> parse --> chunk --> embed --> store in vector DB. Runs once per document version. |
| **Retrieval pipeline** | The runtime process: user query --> embed query --> search vector store --> rerank --> pass top-K chunks to LLM --> return answer with citations. |
| **Hybrid search** | Combining vector similarity (semantic) with BM25 (keyword) for better recall. |
| **Reranking** | A second-pass model that re-scores retrieved chunks by relevance to the query. Improves precision after initial retrieval. |
| **Citation** | A reference back to the exact source clause (e.g. "AC-2, Account Management, p.34"). Every answer must include at least one. |
| **Top-K** | The number of chunks retrieved and passed to the LLM as context. Typical: 3-5. |
| **RRF (Reciprocal Rank Fusion)** | Algorithm to merge ranked results from multiple retrieval methods (vector + BM25) into one list. |

## Compliance / Audit Domain

| Term | Definition |
|------|-----------|
| **NIST SP 800-53** | A US government publication defining security and privacy controls. ~1,000+ controls organized into 20 families. Free, public domain. |
| **Control** | A specific security requirement (e.g. AC-2: Account Management). Has a family prefix, number, title, and description. |
| **Control family** | A group of related controls sharing a prefix (e.g. AC = Access Control, AU = Audit and Accountability). |
| **Control enhancement** | A sub-requirement within a control (e.g. AC-2(1), AC-2(2)). Adds specificity. |
| **Non-conformance (NC)** | A finding where an organization fails to meet a control requirement. What auditors document. |
| **Clause** | A numbered section of a standard. In NIST: a control. In ISO: a clause (e.g. 7.5.1). Used interchangeably with "control" in this project. |
| **Audit** | A systematic review of whether an organization meets the requirements of a standard. |

## Architecture

| Term | Definition |
|------|-----------|
| **Ingestion** | Offline. Happens once. Produces the vector store. |
| **Retrieval** | Runtime. Happens per query. Reads from the vector store. |
| **Source document** | The PDF being ingested. In this project: NIST SP 800-53 Rev 5. |
| **Chunk metadata** | Structured data attached to each chunk: control ID, control title, family, page number. Enables citation generation. |
